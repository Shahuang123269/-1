# RAG：检索增强生成

RAG（Retrieval-Augmented Generation）把“检索”与“生成”组合成一个流程。用户先提出问题，程序从文档或数据库中找出最相关的片段，再把这些片段和问题一起交给 LLM 生成回答。

在第九步中，知识库就是本项目 `notes/` 文件夹中的 Markdown 和文本文件。程序不会把整份笔记直接塞给模型，而是先把笔记切成小片段，用 BM25 关键词排序找出最相关的几个片段。最后，DeepSeek 只依据这些片段回答，并显示 `【文件名#片段N】` 来源标记。

RAG 解决的问题是：模型的训练知识不等于你的私有、最新或项目专属资料。更新笔记后重新检索即可使用新知识，不需要重新训练模型。

RAG 的基本流程是：`问题 → 检索 → 相关片段 → LLM 生成带来源的回答`。检索错了，后面的回答也会受影响，所以要先观察检索出的来源是否合理。第九步采用透明的本地 BM25 检索，方便理解；后续可以替换为 embedding 和向量数据库来改善语义检索。
