# Agent Evals：用数据检查质量

LLM 和检索系统都可能在代码没有报错时悄悄变差，所以需要评测（evals）。评测由一组固定问题、预期结果和评分规则组成；每次修改提示词、模型、检索算法或笔记后重新运行，才能发现回归。

第十步评测的是第九步的“检索”阶段，而不是让模型做主观打分。每个样例包含一个问题和期望的笔记来源。程序取前 K 个检索结果，只要期望来源在其中就通过，这个指标叫 Hit@K。

本项目的样例在 `evals/rag_retrieval_cases.json`。你可以增加自己的问题和期望来源。运行评测后，如果某个样例失败，先检查实际检索到的文件，再决定是修正笔记、调整问题，还是改进检索算法。

对生成阶段，第十步还提供了来源标记校验：回答中的每一个 `【文件名#片段N】` 必须在本轮实际检索到的片段中。这不是完整的事实正确性评测，但能阻止“编造引用”这一类常见问题。
